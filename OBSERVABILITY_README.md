# Observability + Routing Plugins

This document describes the observability and pluggable routing engine architecture for OptiML.

## Overview

OptiML now includes:
- **Pluggable routing engine architecture** for integrating emerging routing research (quality predictors, bandits, offline replay)
- **Deep observability** with traces, request logs, metrics, and dashboards
- **Structured request logging** for every LLM request
- **Trace spans** for gateway receive, route decision, provider calls, fallbacks, and post-processing
- **Persistent logging** to Supabase/Postgres with safe defaults

## Architecture

### Routing Plugin System

The routing system is built around a pluggable `Router` interface that allows different routing strategies to be swapped in without rewriting the API gateway.

#### Router Interface

Located in `routers/base.py`:

```python
from routers.base import Router, RouteInput, RouteDecision

class Router(ABC):
    @abstractmethod
    def select_model(self, route_input: RouteInput) -> RouteDecision:
        """Select the best model/provider combination"""
        pass
```

#### Available Routers

1. **BaselineRouter** (default)
   - Heuristic routing based on:
     - Capabilities filters
     - Cost estimates
     - Latency priors
   - Falls back to cheaper models on budget constraints

2. **ExperimentalRouter** (stub)
   - Placeholder for future research integrations
   - Currently delegates to BaselineRouter
   - Can be extended to load JSON/DB config and call learned predictors or bandit policies

### Observability System

#### Request Logging

Every LLM request is logged with:
- `request_id` and `trace_id` (generated by middleware)
- Routing decision (provider, model, reason code, policy name/version)
- Token usage (prompt, completion, total)
- Cost and latency
- Outcome (success, fallback_success, failure, refused)
- Failure reason (timeout, rate_limit, provider_5xx, invalid_json, tool_error, safety, unknown)
- Validation results (json_valid, schema_valid)

#### Trace Spans

Each request generates multiple spans:
- `gateway_receive`: Request received at gateway
- `route_decision`: Routing decision made
- `provider_call`: Primary provider call
- `fallback_call`: Fallback provider calls (if any)
- `post_processing`: Response post-processing
- `validation`: JSON/schema validation

#### Database Tables

1. **request_logs**: One row per request
2. **request_spans**: One row per span/attempt
3. **model_stats_daily**: Daily aggregated statistics for dashboards
4. **replay_logs**: Offline replay results

## Setup

### 1. Database Migration

Run the SQL migration to create observability tables:

```bash
# In your Supabase SQL editor or via psql
psql -h your-db-host -U your-user -d your-db -f migration_add_observability_tables.sql
```

Or execute the SQL file contents in your Supabase dashboard.

### 2. Environment Variables

Add these to your `.env` file:

```bash
# Observability settings
OPTIML_STORE_PROMPTS=false              # Set to true to store prompts (default: false)
OPTIML_ROUTER=baseline                   # Router to use: baseline or experimental
OPTIML_ENABLE_REPLAY=false               # Enable replay endpoint (default: false)

# Optional: Experimental router config
OPTIML_ROUTER_CONFIG_PATH=/path/to/config.json
```

### 3. Running Locally

```bash
# Install dependencies
pip install -r requirements.txt

# Set environment variables
export SUPABASE_URL=your_supabase_url
export SUPABASE_KEY=your_supabase_key
export OPTIML_STORE_PROMPTS=false
export OPTIML_ROUTER=baseline

# Run the server
uvicorn main:app --reload
```

## API Endpoints

### Observability Endpoints

#### GET `/observability/summary`

Get daily aggregated statistics for dashboards.

**Query Parameters:**
- `org_id` (optional): Filter by organization
- `project_id` (optional): Filter by project
- `start_date` (optional): Start date (YYYY-MM-DD)
- `end_date` (optional): End date (YYYY-MM-DD)
- `provider` (optional): Filter by provider
- `model` (optional): Filter by model

**Example:**
```bash
curl "http://localhost:8000/observability/summary?org_id=123&start_date=2024-01-01&end_date=2024-01-31"
```

**Response:**
```json
{
  "status": "success",
  "data": [
    {
      "date": "2024-01-15",
      "org_id": "123",
      "provider": "openai",
      "model": "gpt-3.5-turbo",
      "request_count": 100,
      "success_count": 98,
      "failure_count": 2,
      "total_cost_usd": 0.50,
      "avg_latency_ms": 250
    }
  ],
  "count": 1
}
```

#### GET `/observability/requests`

Get recent request logs with optional filters.

**Query Parameters:**
- `org_id` (optional): Filter by organization
- `project_id` (optional): Filter by project
- `start_date` (optional): Start date (ISO format)
- `end_date` (optional): End date (ISO format)
- `provider` (optional): Filter by provider
- `model` (optional): Filter by model
- `outcome` (optional): Filter by outcome (success, fallback_success, failure, refused)
- `limit` (optional): Maximum results (default: 100, max: 1000)

**Example:**
```bash
curl "http://localhost:8000/observability/requests?org_id=123&limit=50"
```

#### GET `/observability/requests/{request_id}/trace`

Get full trace for a specific request (request + all spans).

**Example:**
```bash
curl "http://localhost:8000/observability/requests/abc-123-def/trace"
```

**Response:**
```json
{
  "status": "success",
  "request": {
    "request_id": "abc-123-def",
    "trace_id": "xyz-456-ghi",
    "chosen_provider": "openai",
    "chosen_model": "gpt-3.5-turbo",
    "outcome": "success",
    "latency_ms": 250
  },
  "spans": [
    {
      "span_type": "gateway_receive",
      "duration_ms": 1,
      "status": "success"
    },
    {
      "span_type": "route_decision",
      "duration_ms": 5,
      "status": "success"
    },
    {
      "span_type": "provider_call",
      "provider": "openai",
      "model": "gpt-3.5-turbo",
      "duration_ms": 240,
      "status": "success"
    }
  ]
}
```

#### POST `/observability/replay`

Replay a stored request against a specified model/provider (admin-only).

**Note:** Requires `OPTIML_ENABLE_REPLAY=true`

**Headers:**
- `Authorization: Bearer <api_key>`

**Body:**
```json
{
  "request_id": "abc-123-def",
  "provider": "anthropic",
  "model": "claude-3-haiku",
  "prompt_text": "Optional: if original prompt wasn't stored"
}
```

**Example:**
```bash
curl -X POST "http://localhost:8000/observability/replay" \
  -H "Authorization: Bearer your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "abc-123-def",
    "provider": "anthropic",
    "model": "claude-3-haiku"
  }'
```

## Implementation Details

### Request ID and Trace ID

Every request automatically gets:
- `request_id`: Unique identifier for the request (UUID)
- `trace_id`: Groups related spans (UUID)

These are added by the `ObservabilityMiddleware` and included in response headers:
- `X-Request-ID`
- `X-Trace-ID`

### Prompt Storage

By default, prompts are **not stored** for privacy. To enable:

```bash
export OPTIML_STORE_PROMPTS=true
```

When enabled, prompts are:
- Truncated to 10,000 characters
- Stored in `request_logs.prompt_text` and `request_logs.response_text`

### Fallback Chain

The routing system supports fallback chains. If the primary provider/model fails with a retriable error (timeout, rate limit, 5xx), the system will automatically try fallback options in order.

Retriable errors:
- `timeout`
- `rate_limit`
- `provider_5xx`

Non-retriable errors:
- `invalid_json`
- `tool_error`
- `safety`
- `unknown`

### Daily Statistics

Daily statistics are aggregated in the `model_stats_daily` table. This is typically updated:
- Asynchronously after each request (simplified implementation)
- Or via a background job that processes `request_logs` periodically

## Extending the Router System

To add a new router:

1. Create a new router class in `routers/`:

```python
from routers.base import Router, RouteInput, RouteDecision

class MyCustomRouter(Router):
    @property
    def name(self) -> str:
        return "my_custom"
    
    @property
    def version(self) -> str:
        return "1.0.0"
    
    def select_model(self, route_input: RouteInput) -> RouteDecision:
        # Your routing logic here
        return RouteDecision(
            provider="openai",
            model="gpt-4",
            fallback_chain=[],
            parameters={},
            reason_code="my_custom_logic",
            route_policy_name=self.name,
            route_policy_version=self.version
        )
```

2. Update `routers/router_manager.py`:

```python
def get_router() -> Router:
    router_type = os.getenv("OPTIML_ROUTER", "baseline").lower()
    
    if router_type == "my_custom":
        return MyCustomRouter()
    # ... existing routers
```

3. Set environment variable:

```bash
export OPTIML_ROUTER=my_custom
```

## Troubleshooting

### Observability data not appearing

1. Check that the database migration ran successfully
2. Verify environment variables are set correctly
3. Check Supabase connection in logs
4. Ensure requests are going through the `/v1/prompt` endpoint (which has observability)

### Replay endpoint returns 403

- Ensure `OPTIML_ENABLE_REPLAY=true` is set
- Verify you're using a valid admin API key in the Authorization header

### High latency in dashboards

- The `model_stats_daily` table should be used for dashboard queries (not `request_logs`)
- Consider adding indexes if queries are slow
- Use date range filters to limit data
